# Session #813 — fix(ios): BackgroundTaskManager/cache wiring race on cold launch

**Issue:** [#813](https://github.com/tiagofur/solennix/issues/813)
**Branch:** `fix/ios-bgtask-cache-race-813`
**Worktree:** `/Users/tiagofur/dev/solennix-ios-813`
**Type:** bug · Priority: medium · Platform: iOS

## Problem

`BackgroundTaskManager` was constructed in a `.task` separate from the one
building `CacheManager` (SolennixApp.swift). SwiftUI `.task` modifiers fire as
independent async contexts, so the BG manager could capture a `nil`
`cacheManager` at init time. Once captured as nil, every background refresh
silently skipped cache/widget persistence (the `try? cacheManager?.cache…`
calls were no-ops) until the next app launch.

**Judgment Day:** B-012 / A-019 (WARNING real / theoretical)

## Root cause

- `SolennixApp.swift` had two `.task` modifiers:
  - `.task` (line ~152): built `CacheManager` + started `WidgetSyncCoordinator`.
  - `.task` (line ~300): built `BackgroundTaskManager`, capturing `cacheManager`
    at construction time.
- Order is not guaranteed; if the BG `.task` ran first, `cacheManager` was nil
  and stayed nil for the manager's lifetime (it was a `let`).
- `BackgroundTaskManager` used `private let cacheManager: CacheManager?` and
  optional-chained through it in `performRefresh`.

## Fix

Mirror the `WidgetSyncCoordinator.start(cache:)` pattern (issue #831):
construct the BG manager eagerly, attach the cache once available.

### `ios/Solennix/BackgroundTaskManager.swift`
- `cacheManager` changed from `private let …?` → `private weak var …?`
  (weak: app owns the cache; mirrors WidgetSyncCoordinator).
- `init` keeps an optional `cacheManager` param (default `nil`) for
  backward-compat, but production no longer passes it.
- New `attach(cache:)` method.
- New `internal var isReadyForRefresh` seam: `authManager.isAuthenticated &&
  cacheManager != nil` — extracted so the guard is unit-testable without a
  real network refresh.
- `performRefresh` now guard-unwraps `cacheManager` and logs a warning if nil
  (#813 cold-launch race) instead of silently no-oping.
- Added `os.log` logger (parity with WidgetSyncCoordinator).

### `ios/Solennix/SolennixApp.swift`
- Consolidated BG manager construction into the SAME `.task` that builds the
  cache (the one that also starts WidgetSyncCoordinator). This guarantees the
  manager sees a non-nil cache before any BG refresh can fire.
- Removed the separate `.task` that constructed the BG manager.
- The cache `.task` now: builds cache → starts WidgetSyncCoordinator → builds
  BG manager → `attach(cache:)` → sets `BackgroundTaskManager.shared` →
  schedules refresh. On re-entry (idempotent), it only re-attaches the cache.

### `ios/SolennixTests/BackgroundTaskManagerTests.swift` (new)
6 tests pinning the readiness contract:
- `testNotReadyWhenCacheNotAttachedEvenIfAuthenticated` — the #813 guard
- `testReadyAfterAttachCache` — fix verified
- `testNotReadyWhenNotAuthenticatedEvenWithCache` — auth gate preserved
- `testAttachIsIdempotent` — re-entry safety
- `testInitWithCacheAttachedIsReady` — legacy init path
- `testSharedWeakReferenceRoundTrip` — `.shared` rendezvous contract

Added to `SolennixTests` target via `xcodeproj` gem (project uses manual
pbxproj, not file-system sync).
