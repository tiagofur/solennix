# Sesión — Issue #879

- **Issue:** #879 — feat(web): Master-detail split pane for Events, Clients, Products at xl+ breakpoints
- **Estado:** done
- **Branch:** `feat/web-master-detail-split-pane-879`
- **Scope decision:** Clients + Products (Events/EventSummary 82KB monolítico queda para follow-up; Inventory fuera). Forms navegan a full-page.

## Root cause / motivation
PRODUCT.md establece desktop como primario para web, pero las list views solo usan full-page navigation. No existe master-detail split a breakpoints anchos. iOS iPad/macOS tiene two-column detail; web se sentía como mobile SPA con sidebar. Judgment Day: A-017 / B-020 (score split-pane 2–3/10).

## Cambios
- **Infraestructura compartida:**
  - `hooks/useBreakpoint.ts` (nuevo): `useIsXl()` con `useSyncExternalStore` + `matchMedia('(min-width: 1280px)')`, SSR-safe. Reemplaza la ausencia de cualquier hook de breakpoint en el codebase (solo existía `matchMedia` para dark mode en ThemeContext).
  - `components/SplitPane.tsx` (nuevo): contenedor grid responsive `grid-cols-1 xl:grid-cols-[minmax(0,1fr)_minmax(380px,520px)]` con scroll independiente por pane. DRY — Clients y Products comparten el mismo contenedor. Template basado en `TeamCalendarPage.tsx:329` (`lg:grid-cols-[380px_1fr]`).

- **Clients (panel-ready):**
  - `ClientDetails.tsx`: extraído `ClientDetailPanel({ clientId, embedded?, onDeleted? })`. El componente ruta `ClientDetails` queda como wrapper delgado (`useParams` → `<ClientDetailPanel clientId={id} />`). Modo `embedded`: omite `<Breadcrumb>` + back button; delete success llama `onDeleted` en vez de `navigate('/clients')`.
  - `ClientList.tsx`: en xl envuelve el contenido en `<SplitPane master={listContent} detail={detailPanel} />`. Row click → `setSearchParams({selected: id})` en xl, `navigate('/clients/:id')` en < xl. Row activa highlight (`bg-surface-alt ring-1 ring-inset ring-primary/30` + `aria-current`). Empty state "Seleccioná un cliente" cuando no hay selección.

- **Products (panel-ready):**
  - `ProductDetails.tsx`: extraído `ProductDetailPanel({ productId, embedded?, onDeleted? })`. Mismo patrán que Clients. El `loadDemandForecast` con `eventService.getAll()` se mantiene (solo corre con selección activa, mismo coste que hoy).
  - `ProductList.tsx`: espejo de ClientList — `<SplitPane>` en xl, `selected` param, row highlight.

- **i18n:** `common.json` (es + en): sección `split` con `select_client` / `select_client_hint` / `select_product` / `select_product_hint`.

- **Tests:**
  - `useBreakpoint.test.ts` (nuevo, 5 casos): false <1280, true ≥1280, query correcta, update en boundary crossing (con `act`), cleanup de listener.
  - `ClientList.test.tsx`: +3 casos xl (select sin navigate, empty state, detail panel en rail con `?selected=`). Mock de `useBreakpoint` + stub de `ClientDetailPanel`.
  - `ProductList.test.tsx`: +2 casos xl (empty state, detail panel en rail). Mock de `useBreakpoint` + stub de `ProductDetailPanel`.
  - `ClientDetails.test.tsx` (22 casos) y `ProductDetails.test.tsx` (11 casos): todos verdes — el refactor a wrapper delgado preservó compatibilidad de ruta.

## Notas
- **No se tocó Events/EventSummary** (82KB monolítico, 6 tabs, `max-w-5xl`, 9 hooks, useParams/useNavigate acoplado). Queda para follow-up — el refactor requiere decoupling significativo.
- **No se tocó Inventory.** Queda para follow-up.
- **Forms navegan a full-page** (decisión del usuario): el pane muestra detalle read-only + quick actions; click en editar navega a `/clients/:id/edit` o `/products/:id/edit`.
- **URL refleja selección:** `/clients?selected=<id>`, `/products?selected=<id>` — preserva otros search params (filtros, sort, page).
- **Scroll independencia:** `<main>` en Layout.tsx es `flex-1 overflow-y-auto` dentro de panel `flex-col overflow-hidden` → el `SplitPane` con `xl:h-full xl:min-h-0` + cada pane `xl:overflow-y-auto` da scroll independiente. Click en row no pierde scroll de lista.
- **`useSyncExternalStore`** elegido sobre `useState`+`useEffect` para evitar tearing y ser SSR-safe (getServerSnapshot returns false).
- **jsdom no implementa `matchMedia`** — los tests de lista mockean `useBreakpoint` directamente (`vi.mock`).
