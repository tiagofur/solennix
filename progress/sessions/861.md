# Sesión — Issue #861

- **Issue:** #861 — perf(web): Dashboard and EventList fetch full unpaginated event list
- **Estado:** done
- **Branch:** `perf/web-dashboard-eventlist-unpaginated-861`
- **Scope:** Backend (nuevo endpoint) + Web. iOS/Android como follow-up.

## Root cause
`useEvents()` hacía `GET /events` sin params → lista completa sin paginar (uncapped). Se usaba en 3 lugares:
- **Dashboard**: solo para "attention alerts" (filtraba a quoted/confirmed near today + pending balance client-side).
- **EventList**: solo para CSV export sin filtros + fallback del count del header.
- **OnboardingChecklist**: solo `events.length > 0`.

Las 3 plataformas triplicaban la misma lógica client-side sobre la lista completa de eventos + pagos. iOS la duplicaba internamente (`DashboardViewModel` + `PendingEventsViewModel`). Divergencia: web no tenía `quote_urgent` pero iOS/Android sí.

## Cambios

### Backend (nuevo endpoint `GET /dashboard/attention`)
- **`repository/dashboard_repo.go`**: nuevo struct `AttentionItem` + método `GetAttention(ctx, userID)`. Una sola query SQL con CTE que suma payments por evento (`LEFT JOIN ... COALESCE(SUM(p.amount),0)`), clasifica `reason` con `CASE WHEN` (payment_due / overdue_event / quote_urgent), filtra los que matchean, ORDER BY event_date ASC, LIMIT 50.
- **`handlers/interfaces.go`**: añadido `GetAttention` a `DashboardRepository`.
- **`handlers/dashboard_handler.go`**: nuevo método `GetAttention(w, r)` — pass-through trivial.
- **`router/router.go`**: registrado `GET /dashboard/attention` en el grupo `/dashboard`.
- **`handlers/dashboard_handler_test.go`**: `TestGetAttention` (3 casos: success con items, empty array, repo error).
- **`handlers/mocks_test.go`**: añadido `GetAttention` al `MockDashboardRepo`.
- **`docs/openapi.yaml`**: endpoint + schema `AttentionItem` documentados.

### Web
- **`types/dashboard.ts`**: nuevo tipo `AttentionItem` + `AttentionReason`.
- **`services/dashboardService.ts`**: `getAttention()`.
- **`hooks/queries/queryKeys.ts`**: `dashboard.attention` key.
- **`hooks/queries/useDashboardQueries.ts`**: nuevo hook `useDashboardAttention()` (staleTime 60s).
- **`pages/Dashboard.tsx`**: reemplazado `useEvents()` + `usePaymentsByEventIds` + toda la lógica client-side de `attentionAlerts` por `useDashboardAttention()`. El useMemo ahora agrupa por `reason` (payment_due / overdue_event / quote_urgent) en vez de re-computar balances. `DashboardAttentionItem` interface simplificada (eventId, eventDate, serviceType, clientName en vez de full `DashboardEvent`). `handleCompleteEvent` y `handleOpenPaymentModal` leen del array de attention items. Eliminados imports `Payment`, `addDays`, `useEvents`, `usePaymentsByEventIds`.
- **`pages/Events/EventList.tsx`**: removido `useEvents()` + `allEvents`. CSV export ahora usa la página actual (`paginatedEvents`). `headerCount` usa `paginatedQuery.data?.total`.
- **`components/OnboardingChecklist.tsx`**: `useEvents()` → `useEventsPaginated({page:1, limit:1})`, verifica `eventsPage?.total > 0`.
- **`i18n/locales/{es,en}/dashboard.json`**: nuevas keys `quote_urgent_title` / `quote_urgent_desc` (web ahora muestra esta tercera categoría que antes no tenía).

### Tests
- **`Dashboard.test.tsx`**: `useDashboardAttention` mockeado con `mockAttentionQuery` controlable. Los 4 tests de attention reescritos para proveer `AttentionItem[]` directo (antes mockeaban `eventService.getAll` + `paymentService.getByEventIds` para ejercer la lógica client-side).
- **`OnboardingChecklist.test.tsx`**: mock actualizado a `useEventsPaginated` con shape `{ total, data }`.
- **`EventList.test.tsx`**: sin cambios (ya no depende de `useEvents`).

## Verificación

## Notas
- **Query SQL**: la ventana es `event_date >= CURRENT_DATE - INTERVAL '30 days' AND event_date <= CURRENT_DATE + INTERVAL '14 days'` — cubre overdue (lookback 30d) + quote_urgent (forward 14d) + payment_due (forward 7d, incluido en el rango). LIMIT 50.
- **El endpoint es aditivo** — no rompe iOS/Android que siguen usando `getAll(events)` hasta que migren.
- **CSV export de EventList** ahora exporta la página actual. El export completo requeriría un endpoint dedicado (fuera de scope).
- `queryKeys.events.all` se mantiene como key de invalidación aunque `useEvents()` ya no se usa desde Dashboard/EventList/OnboardingChecklist.
