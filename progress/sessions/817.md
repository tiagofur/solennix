# Session #817 — refactor(ios): Cancel view-scoped Tasks on navigation

## Problem

Widespread fire-and-forget `Task { await ... }` in SwiftUI View button actions
and confirm dialogs without view-lifetime cancellation. Fast navigation away
after tapping save/delete could complete the async operation on a detached view,
updating stale state or showing orphan toasts on the wrong screen.

**Judgment Day:** A-016 (WARNING theoretical)

## Solution

Created a reusable `ViewScopedTask` helper in `SolennixDesign` and applied it to
25 view files covering the two highest-risk clusters:

1. **Forms with `dismiss()`-after-await** (~19 files): save/delete buttons that
   call `dismiss()` after an async operation. If the user navigates back during
   the await, the `dismiss()` fires on a stale view.
2. **Orphan-toast list views** (6 files): `toastManager.showUndo(onExpire:)`
   closures that fire `Task { await vm.confirmDelete(); toastManager.show() }`.

### The `ViewScopedTask` helper (`SolennixDesign/ViewModifiers.swift`)

```swift
@MainActor
public final class ViewScopedTask {
    fileprivate var current: Task<Void, Never>?
    public func start(_ operation: @escaping @Sendable () async -> Void) {
        current?.cancel()
        current = Task(operation: operation)
    }
    fileprivate func cancel() { current?.cancel(); current = nil }
}

public extension View {
    func viewScopedTask(scoped: Binding<ViewScopedTask?>) -> some View {
        modifier(ViewScopedTaskModifier(scoped: scoped))
    }
}
```

**Usage pattern:**
```swift
@State private var scoped: ViewScopedTask?

var body: some View {
    Form { ... }
        .viewScopedTask(scoped: $scoped)  // cancels on .onDisappear
        .toolbar {
            Button("Save") {
                scoped?.start {              // replaces Task { }
                    if await viewModel.save() { dismiss() }
                }
            }
        }
}
```

## Scope notes

This PR covers the two highest-risk clusters. Remaining LOW-risk fire-and-forget
tasks (retry buttons, token registration, language reporting) are intentionally
left as `Task {}` — they are idempotent and don't mutate view state. The
`ViewScopedTask` helper is now available for incremental adoption in future
views and Events detail/sheet views not covered here.
