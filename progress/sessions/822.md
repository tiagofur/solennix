## Problem

Two `BiometricGateView` implementations existed with divergent behavior:

| Aspect | `SolennixFeatures` (canonical, public) | `ContentView.swift` (shell, internal) |
|--------|----------------------------------------|---------------------------------------|
| Localization | `AuthStrings` via FeatureL10n (dynamic) | `LocalizedStringKey("auth.unlock.*")` (hardcoded keys) |
| Biometric icon | Detects faceID / touchID / none dynamically | Always `"faceid"` |
| Fallback on failure | `presentPasswordFallback()` — keeps server session | `signOut()` after 3 attempts — **revokes session on all devices** |
| Dynamic Type | `@ScaledMetric` icon scaling | Fixed sizes |
| Design system | `Spacing`, `PremiumButton` | Raw values, `Button(.borderedProminent)` |

The shell-local duplicate shadowed the canonical Features-module implementation
due to Swift's lexical scope resolution. Fixes applied to the Features version
(left a stale shell duplicate); the shell version carried a latent bug where
biometric fallback revoked the session on all devices.

## Fix

Removed the internal `BiometricGateView` from `ContentView.swift` (86 lines).
`ContentView` now resolves `BiometricGateView()` to the `public` implementation
in `SolennixFeatures.Auth.Views.BiometricGateView` (already imported).

This consolidates to the superior implementation: dynamic l10n, correct
biometric type detection, `@ScaledMetric` accessibility, and the safe
`presentPasswordFallback()` (no cross-device session revocation).
